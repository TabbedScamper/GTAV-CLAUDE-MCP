# GTA V RPF Archives — Complete Technical Reference

Everything about Rockstar's **RPF** (RAGE Package File) archives, assembled from primary sources:
CodeWalker source (`dexyfex/CodeWalker`), FiveM RE source (`citizenfx/fivem`), gta-toolkit
(`Neodymium146`), the alloc8or native DB, the GTAMods wiki, and the RAGE.MP/alt:V schema docs.

**Confidence tags:** **[C]** confirmed from primary source (tool source / native DB) · **[COMM]**
community consensus / mod-menu behavior, high confidence but not single-source RE · **[I]**
inferred / verify on your own binary.

> Companion to `DISCOVERIES.md` (our own hands-on Claude FM findings). This file is the *format*
> reference; DISCOVERIES is the *applied* one.

---

## 0. TL;DR for this project

- **GTA V Legacy = RPF7. Enhanced (Gen9, 2025) = RPF8-family** (different structure + new keys from
  `gta5_enhanced.exe`; Gen8 assets crash Enhanced unless converted). We target Legacy → **RPF7**.
- **Encryption type is a header field.** Four values: `NONE`, `OPEN` ("OPEN"), `AES`, `NG`. Mods ship
  **OPEN** so no re-encryption is needed.
- **Read NG = easy; write NG = the wall.** Every open-source library can *decrypt* NG (keys live in
  the exe) but *cannot re-encrypt* NG — the encrypt tables aren't in the exe and aren't generated by
  the normal load path. **OpenIV (GUI Edit mode) is the only practical NG writer.** This is exactly
  why our CodeWalker.Core pipeline can only emit OPEN rpfs (matches `DISCOVERIES.md` §3).
- **Hot-reload verdict (for the other thread):** mounting a *new* rpf at runtime is an **engine-side**
  operation (`fiPackfile` + `CExtraContentManager`) — **no script native does it**. Mod menus do it by
  native hooking. **Vehicles/peds/models/handling/IPL hot-load works; AUDIO is load-once → restart.**
  Our radio is the hard case, but we already sidestep it (NAudio plays the audio; the DLC only does the
  static wheel-station + icon).

## 1. Version history & magic

First 4 bytes = a uint32 version tag. ASCII `RPFx` stored little-endian (e.g. `RPF7` → on-disk bytes
`37 46 50 52` → reads as `0x52504637`).

| Version | uint32 | Games |
|---|---|---|
| RPF0 | `0x52504630` | R\* Table Tennis |
| RPF2 | `0x52504632` | GTA IV |
| RPF3 | `0x52504633` | GTA IV audio, MC:LA |
| RPF4 | `0x52504634` | Max Payne 3 |
| RPF6 | `0x52504636` | RDR (2010) |
| **RPF7** | **`0x52504637`** | **GTA V Legacy, GTA Online, FiveM** |
| RPF8 | `0x52504638` | RDR2; **GTA V Enhanced is RPF8-family** [I on exact magic] |

**RPF8 key change:** entries are keyed by **hash, not name** — no filename string blob; names are
recovered from external nametables. [C]

## 2. RPF7 header (16 bytes, 4 LE uint32) [C]

| Off | Size | Field | Notes |
|---|---|---|---|
| 0x00 | 4 | `Version` | `0x52504637`; parser throws otherwise |
| 0x04 | 4 | `EntryCount` | number of TOC entries |
| 0x08 | 4 | `NamesLength` | byte length of the names blob |
| 0x0C | 4 | `Encryption` | encryption-type tag (§7) |

After the header: `EntryCount × 16` bytes of **entries**, then `NamesLength` bytes of **names**. Both
buffers are decrypted whole (per the type) before parsing.

**Block unit = 512 bytes for RPF7** (`>>9` / `&0x1FF` math). The header region is rounded up to whole
512-byte blocks; file data follows in 512-byte blocks. (The wiki's "2048" is an RPF0/RPF2 figure;
builders often align *archive/nested-rpf starts* to 2048, but RPF7's granularity is **512**.) [C]

---

## 3. TOC entry structures (every entry = 16 bytes) [C]

Classify by the **second uint32** (`x`):
```
if      (x == 0x7FFFFF00)        -> Directory
else if ((x & 0x80000000) == 0)  -> Binary file   (high bit clear)
else                             -> Resource file (high bit set)
```

### 3a. Directory
| Off | Field | |
|---|---|---|
| 0x00 | `NameOffset` | byte offset into names blob |
| 0x04 | `0x7FFFFF00` | identifier (must match) |
| 0x08 | `EntriesIndex` | first child index in the flat entry array |
| 0x0C | `EntriesCount` | child count |

Directory owns the contiguous range `[EntriesIndex, EntriesIndex+EntriesCount)` → forms the tree.
Entry 0 = root.

### 3b. Binary file (uncompressed or zlib) — first 8 bytes are a packed uint64
| Bits | Field | Width |
|---|---|---|
| `buf & 0xFFFF` | `NameOffset` | 16b |
| `(buf>>16) & 0xFFFFFF` | `FileSize` | 24b — **on-disk (compressed) size** |
| `(buf>>40) & 0xFFFFFF` | `FileOffset` | 24b — **in 512-byte blocks** |

| Off | Field |
|---|---|
| 0x08 | `FileUncompressedSize` (u32) |
| 0x0C | `EncryptionType` (u32): 0=plain, 1=encrypted (else throws) |

**`FileSize == 0` ⇒ stored uncompressed** (use `FileUncompressedSize`); **`FileSize > 0` ⇒
zlib-compressed** to that byte count.

### 3c. Resource file (RSC)
| Off | Size | Field |
|---|---|---|
| 0x00 | 2 | `NameOffset` (u16) |
| 0x02 | 3 | `FileSize` (LE, on-disk) |
| 0x05 | 3 | `FileOffset` (LE, `&0x7FFFFF`, in 512-byte blocks) |
| 0x08 | 4 | `SystemFlags` (virtual/system page flags) |
| 0x0C | 4 | `GraphicsFlags` (physical/graphics page flags) |

If `FileSize == 0xFFFFFF`, the true size comes from the RSC7 header, byte-scrambled as
`buf[7]<<0 | buf[14]<<8 | buf[5]<<16 | buf[2]<<24` (genuinely that strange — verbatim from CodeWalker).

**Seek to data:** `position = StartPos + FileOffset*512`. Block count rounds up:
`b1 = bytes>>9; b0 = bytes&0x1FF; count = b1 + (b0?1:0)`.

---

## 4. Names table [C]
One blob of `NamesLength` bytes after the entries. Each `NameOffset` = byte offset to a
null-terminated ASCII string. Names are deduped on write (name→offset dict). Root name is empty.
(Absent in RPF8 — hash-keyed.) Engine lookups are by **JOAAT** (Jenkins one-at-a-time, lowercased) —
wrong casing/typo → asset silently not found.

---

## 5. Resources (RSC7) & page flags [C]
Resource data starts with a 16-byte **RSC7** header: magic `0x37435352` (`RSC7`), `version`,
`SystemFlags`, `GraphicsFlags`. On extract, skip 16 bytes, then DEFLATE-decompress.

A resource is a **paged memory image**: a system (virtual) segment + a graphics (physical) segment,
each sized by a packed page-flags uint32:
```
ss = flags & 0xF              -> baseSize = 0x200 << ss
size = baseSize * ( ((flags>>27)&1)*1 + ((flags>>26)&1)*2 + ((flags>>25)&1)*4
                  + ((flags>>24)&1)*8 + ((flags>>17)&0x7F)*16 + ((flags>>11)&0x3F)*32
                  + ((flags>>7)&0xF)*64 + ((flags>>5)&3)*128 + ((flags>>4)&1)*256 )
```
High nibble (`flags>>28`) = resource type/version; `type == 0x9` flags AES/encrypted resources.

---

## 6. Compression [C]
RPF7 file data is **zlib/DEFLATE without a zlib header** (raw `DeflateStream`). Signaled per §3b
(`FileSize==0` = stored). Resources: strip 16-byte RSC7 header, then inflate. Nested `.rpf` and `.awc`
are stored as-is (not recompressed).

## 7. Encryption — types, AES, NG

### 7.1 The header `Encryption` field [C]
| Name | uint32 | Meaning |
|---|---|---|
| `NONE` | `0x00000000` | unencrypted |
| `OPEN` | `0x4E45504F` | ASCII "OPEN" — OpenIV's unencrypted marker (the modding format) |
| `AES` | `0x0FFFFFF9` | AES-256 ECB TOC |
| `NG` | `0x0FEFFFFF` | "Next Gen" per-file keyed cipher (retail PC rpfs) |

NONE/OPEN both = "TOC not encrypted." Per-entry data can be flagged encrypted independent of the TOC.

### 7.2 AES [C]
AES-**256**, 128-bit block, **ECB**, no padding. Processed in 16-byte blocks; trailing partial block
copied through untouched. CodeWalker applies the transform **once** per block (`rounds=1` default).
⚠️ The GTAMods "AES ×16" figure is **GTA IV**, not GTA V — don't apply it here. Key = one 32-byte
`PC_AES_KEY`.

### 7.3 NG ("Next Gen" / NTL) — the table cipher [C]
A custom **17-round, LUT-driven** block cipher with a **per-file key** selected by `(name, size)`:
```
hash   = GTA5Hash(name)                       // Jenkins-family
keyidx = (hash + length + 61) % 101           // 61 == (101 - 40)
key    = PC_NG_KEYS[keyidx]                    // 101 keys, each 272 bytes = 17 subkeys × 16
```
- `PC_NG_DECRYPT_TABLES` = `[17][16][256]` uint32 LUTs. `PC_LUT` = 256-byte hash table.
- Block = four LE 32-bit words. **Decrypt:** RoundA at indices **{0,1,16}**, RoundB at **2–15**.
  - *RoundA* ("straight"): word k = `T[4k+0..3][data...] ^ key`.
  - *RoundB* ("diffusing", ShiftRows-like permutation): each word mixes 4 columns, e.g.
    `x1 = T[0][d0]^T[7][d7]^T[10][d10]^T[13][d13]^key`.
- **Encrypt** walks rounds in reverse using `PC_NG_ENCRYPT_TABLES` (RoundA at 16, then 15→2 RoundB_LUT,
  then 1,0 RoundA) — XOR key *before* substitution.
- Renaming or resizing an NG file breaks decryption (changes the key index) unless re-keyed.

### 7.4 Key extraction from the exe [C] (mechanism only — no secret bytes)
Keys/LUTs are **embedded in `GTA5.exe`** (or `gta5_enhanced.exe`). Tools find them by **SHA1-of-region
matching** (robust to patch offset moves): AES key (1 hash), 101 NG keys (101 hashes), decrypt tables
(272 = 17×16 hashes), hash LUT. That's why the exe must be present; CodeWalker caches results to
`Magic.dat`. The keys are Rockstar's — tools ship only the *finder*, you supply your owned exe.

### 7.5 The read/write asymmetry — **the most important practical fact** [C]
- The exe contains **only DECRYPT tables**. No encrypt tables.
- To **write NG** you need `PC_NG_ENCRYPT_TABLES`, which CodeWalker **derives** (GF(2) Gaussian
  solver `RandomGauss.Solve()` for rounds 0/1/16; `LookUpTableGenerator.BuildLUTs2()` for 2–15) — an
  expensive precompute **the normal load path does not run**.
- So `GTACrypto.EncryptNG` hard-throws **"Unable to encrypt - tables not loaded."** gta-toolkit
  independently confirms the same wall by **silently downgrading NG→None** on write.
- ⇒ **No open library emits true NG headlessly.** Ship **OPEN** instead.

## 8. Runtime loading & mounting (the engine file system)

### 8.1 RAGE virtual FS — `rage::fiDevice` family [C]
Paths are `device:/rel/path`; the `device:` token resolves via a mount table (longest-prefix /
priority). Key classes & functions:
- `fiDevice::GetDevice(path, allowRoot)` — **resolve a path to its device** (best live-RE probe: call
  on `"dlcpacks:/"`). `MountGlobal(mountPoint, device, allowRoot)`, `Unmount(...)`,
  `fwEvent OnInitialMount`.
- `fiDeviceRelative` — remaps a mount; `SetPath(path, parent, allowRoot)` + `Mount(mountPoint)`. **How
  DLC devices are created.**
- **`fiPackfile : fiDeviceImplemented`** — **mounts an RPF**: `OpenPackfile(archive, a3, type, a5)`
  (parses header/TOC, sets up decryption) + `Mount(mountPoint)` + `ClosePackfile()`.
- `fiDeviceLocal` (OS FS), `fiEncryptingDevice` (AES/NG key state).

Mount overlays resolve by registration order/priority — later mounts / `overlay` dataFiles shadow
earlier files. Hard mount cap (~500 non-DLC, FiveM raises to 1500).

**Device-name strings (AOB anchors):** `platform:/` (=x64), `common:/`, `update:/`, `dlc:/`,
`dlcpacks:/`, `dlc_<name>:/`, `audio:/`, `x64a:/`…`x64w:/`.

### 8.2 Boot load order [C]
1. Open base archives (`x64*.rpf`, `common.rpf`, `update/update.rpf`) → `OpenPackfile`+`Mount`; update
   overlays common/platform so patched files win. Driven by `OnInitialMount`.
2. Read **`update/update.rpf/common/data/dlclist.xml`** (special-cased string `data/dlclist.xml`).
   Each `<Item>` = `dlcpacks:/<name>/`.
3. Per pack: read **`setup2.xml`** → mount at `dlc_<name>:/` → apply **`content.xml`**.

**`setup2.xml`** (`<SSetupData>`): `deviceName`, `datFile`→content.xml, `nameHash` (joaat),
`type` (`EXTRACONTENT_COMPAT_PACK` vs `EXTRACONTENT_PACK`), `contentChangeSetGroups` (notably
**`GROUP_STARTUP`**).
**`content.xml`** (`<CDataFileMgr__ContentsOfDataFileXml>`): `<dataFiles>` (each: `filename` with
`%PLATFORM%`→x64, `fileType`, flags `overlay/disabled/persistent/locked`) + `<contentChangeSets>`
(`changeSetName`, `filesToEnable`, `filesToDisable`, `mapChanges`). `GROUP_STARTUP`'s `filesToEnable`
is what actually registers the dataFiles into `CDataFileMgr`.

### 8.3 `CExtraContentManager` / `rage::fwExtraContentManager`
Owns DLC discovery, device mounting, the changeset system. The object mod menus hook to mount custom
DLC live. Functions (symbols [COMM], behavior [C via natives/FiveM]):
- `MountUpdate` (mounts update.rpf — discrete hookable step).
- `ExecuteContentChangeset(groupHash)` / `RevertContentChangeset(hash)` — apply/revert (enable/disable
  dataFiles, swap map groups).
- The per-pack mount entry FiveM directly wraps is **`CMountableContent::MountContent(deviceName)`** →
  `fiDeviceRelative::SetPath(citizen:/dlc/<name>/) → Mount("<name>:/")`. **The natural live hook
  target.** [C in FiveM `CitizenMount.cpp`]

### 8.4 Script-native surface & its hard limit [C]
| Native | Hash | Notes |
|---|---|---|
| `EXECUTE_CONTENT_CHANGESET_GROUP_FOR_ALL` | `0x6BEDF5769AC2DC07` | runs a changeset *group* |
| `REVERT_CONTENT_CHANGESET_GROUP_FOR_ALL` | `0x3C1978285B036B25` | reverts a group |
| `GET_CONTENT_TO_LOAD` | `0x24DA7D7667FD7B09` | **stub — returns ""** |
| `GET_CONTENT_TO_LOAD_TYPE` | `0x8B0C2964BA471961` | **stub — returns 0** |
| `IPL_GROUP_SWAP_START/IS_READY/FINISH/CANCEL/IS_ACTIVE` | `0x95A7…/0xFB19…/0xF4A0…/0x63EB…/0x5068…` | swap one IPL group for another |
| `REQUEST_IPL` / `REMOVE_IPL` | `0x41B4893843BBDB74` / `0xEE6C5AD3ECE0A82D` | stream an IPL in/out |

**Every native operates only on already-mounted/registered content.**
`EXECUTE_CONTENT_CHANGESET_GROUP_FOR_ALL` runs a changeset whose dataFiles were registered at boot — it
**cannot open a new rpf from disk.** No script native mounts a fresh DLC rpf → strictly an engine-side
(`fiPackfile` + `CExtraContentManager`) op → requires native-code hooking, not scripting.

### 8.5 mods folder + OpenIV.asi / OpenRPF [C]
- **Legacy:** `OpenIV.asi` (via `dinput8.dll` proxy) hooks file-open → serves `mods\…` if present.
  Read-redirection shim, not a real engine mount.
- **Enhanced:** `OpenRPF` (via `dsound.dll` proxy), same idea; loads OPEN + native archives, **bypasses
  `rpf.cache`** for mods-folder files (v0.2+, kills the need for `rpf.cache.disable`).
- `dlclist.xml` is read once at boot — editing it at runtime does **not** retroactively mount.

### 8.6 `CDataFileMgr` dispatch & reloadability [C present / COMM reload]
67 `fileType` values; the manager dispatches each enabled dataFile to a registered loader. Categories:
- Audio: `AUDIO_GAMEDATA` (dat151), `AUDIO_SOUNDDATA` (dat54), `AUDIO_WAVEPACK` (awc),
  `AUDIO_SPEECHDATA`, `AUDIO_SYNTHDATA`, `AUDIO_DYNAMIXDATA`.
- Vehicles: `VEHICLE_METADATA_FILE`, `HANDLING_FILE`, `CARCOLS_FILE`, `VEHICLE_VARIATION_FILE`, …
- Peds/weapons: `PED_METADATA_FILE`, `WEAPONINFO_FILE`, …
- Containers: `RPF_FILE` (nested archive to mount).

**Re-loadable at runtime** [COMM, mod-menu-proven]: vehicles, peds, weapons, handling, carcols,
models/textures, `RPF_FILE`, map IPL (via `REQUEST_IPL`/group swap).
**Load-once → restart required** [COMM]: the **`AUDIO_*` types** — the audio engine builds its
dat151/dat54 object hash tables + `_AUTOGEN` mappings during early audio init and does not re-scan.

## 9. Hot-reloading a DLC rpf at runtime — what works / what fails

**Who does it:** Stand, 2Take1, Cherax (paid menus) — drop an **unencrypted** `dlc.rpf` (+ generated
`setup2.xml`/`content.xml`) into a watched folder; the menu mounts it natively.
**Mechanism (assembled, [COMM] chain / [C] primitives):** `fiPackfile` →
`OpenPackfile(<path>, true, 0, 0)` → `Mount("dlc_<name>:/")`; create `dlcpacks:/<name>/`
`fiDeviceRelative`; inject the pack into `CExtraContentManager`'s DLC list; run its `GROUP_STARTUP`
changeset so `CDataFileMgr` ingests the dataFiles.
**Works live:** vehicles, peds, weapons, models, textures, handling/carcols, map IPL.
**Fails live:** **audio** (`AUDIO_*`) — silent until full restart. Secondary failure: memory leaks if
too many DLCs are mounted.

**Live-RE target list (for our bridge):**
1. `fiDevice::GetDevice` / `MountGlobal` — probe & create mounts.
2. `fiPackfile::OpenPackfile` + `Mount`; `fiDeviceRelative::SetPath` + `Mount`.
3. `CMountableContent::MountContent(deviceName)` — per-pack mount entry.
4. `CExtraContentManager` instance + DLC list + `ExecuteContentChangeset`/`RevertContentChangeset`
   (drive via `joaat(GROUP_*)`).
5. Pre-build the rpf as **OPEN** to skip the NG key path.

**AOB strings:** `"dlcpacks:/"`, `"dlc_%s:/"`, `"update/update.rpf"`, `"common:/"`, `"platform:/"`,
`"data/dlclist.xml"`, `"content.xml"`, `"setup2.xml"`, `"GROUP_STARTUP"`, `"GROUP_MAP"`/`"GROUP_MAP_SP"`,
`"EXTRACONTENT_COMPAT_PACK"`, `"%PLATFORM%"`, `"%s_AUTOGEN"`, `"fiDeviceLocal::OpenBulk"`.

**Biggest residual unknowns to close in IDA:** (1) `CExtraContentManager` method offsets for our build;
(2) the exact audio-init routine that makes `AUDIO_*` load-once — that one fact decides whether audio
hot-reload is feasible at all (current consensus: no, restart). **The narrower, tractable target for
Claude FM is reloading just the AWC *wavepack* via the streaming system, since our metadata is static.**

## 10. Tooling

| Tool | Read/decrypt | Create | Write OPEN | Write AES | Write **NG** | Headless |
|---|---|---|---|---|---|---|
| **OpenIV** (GUI) | ✓ | ✓ | ✓ | ✓ (Edit) | **✓ only practical NG writer** | ✗ (no CLI) |
| **CodeWalker** (GUI) | ✓ (NG decrypt) | ✓ | ✓ | ✓ | ✗ | partly |
| **CodeWalker.Core** (lib) | ✓ NG decrypt | ✓ `CreateNew` | ✓ | ✓ | ✗ `EncryptNG` throws | **✓ C#/PS** |
| **gta-toolkit/RageLib** (lib) | ✓ | ✓ | ✓ | ✓ | ✗ (NG→None downgrade) | ✓ C# |
| **gtautil** (CLI) | ✓ | ✓ `createarchive` | ✓ | ~`fixarchive` | likely ✗ true NG | **✓ pure CLI** |
| **OpenRPF** (Enhanced) | runtime loader | — | loads OPEN+native | — | — | ASI, not a builder |
| **libertyV** | GTA **IV** only | IV | — | — | — | GUI |

**CodeWalker.Core headless cheat-sheet** (matches `DISCOVERIES.md`):
```csharp
GTA5Keys.LoadFromPath(folder, gen9: false);                 // decrypt tables only (read NG)
var rpf = RpfFile.CreateNew(folder, "dlc.rpf", RpfEncryption.OPEN);   // OPEN — defaults to OPEN
RpfFile.CreateDirectory(dir, name);
RpfFile.CreateFile(dir, name, bytes);
// resources: RpfFile.LoadResourceFile<T>(f, bytes, version) + f.Save(); YtdFile+DDSIO; RelFile/XmlRel
// NG write -> EncryptNG throws "Unable to encrypt - tables not loaded"  => use OpenIV
```
Round-trip caveat: load→save is **not** guaranteed byte-identical (CW issue #195, e.g. ARGB8 textures)
— always validate in-game.

## 12. Common pitfalls
- **512-byte block alignment** (`>>9`); many builders align archive/nested-rpf *starts* to 2048.
- **Mark-of-the-Web:** `Unblock-File` downloaded DLLs (CodeWalker.Core, ScriptHook, OpenRPF) or they
  fail to load.
- **Dropbox/OneDrive/AV lock files mid-write** → `IOException`/truncated rpf. **Build in `%TEMP%`, copy
  in** (we hit this — `DISCOVERIES.md` §3).
- **JOAAT casing** — wrong case/typo hashes wrong → silent no-load.
- **Don't NG-write headlessly** — throws (CodeWalker) or silently downgrades (RageLib).
- **`rpf.cache`** stale → edits "don't apply"; OpenRPF bypasses on Enhanced; else `gtautil buildcache`.
